## Add Pin the Spot question type (T7 canvas type) + T6 sample games

### Summary
Adds **Pin the Spot** (`pin_the_spot`), the team's canvas-based party question type. Players see an
image on their phone, drop a pin on it, and score by how close they are to a hidden target.
Design: [`docs/design-pin-the-spot.md`](docs/design-pin-the-spot.md). The first commit revises it
before implementation, and section 16 lists every change.

Also includes my two T6 game files and a fix for a Redis cleanup leak found while writing the T5 tests.

### What's included
**Backend**
- `services/pin_the_spot.py`: one pure module for the tap check, the `"x,y"` distribution key,
  scoring and the reveal. `game_service`, `gateway` and `report_service` all call it, so the
  type's rules exist in one place, not four copies.
- Scoring: full points inside `r_full`, 0 beyond `r_zero`, linear in between, rounded half-up to
  2 dp. Vertical distance is scaled by the image's aspect ratio so circles stay round.
- Validation: `validate_pin_the_spot` runs on **create, import and update**. Update checks the
  merged stored + requested values; before this, update only validated `put_in_order`.
  Once a question has answers, its image and type are locked (409); the target and radii can change.
- The gateway rejects malformed taps (`{x, y}` must be finite, non-bool numbers in 0–1).
- The HTML session report draws the image, both circles and every tap as inline SVG.
- No migration: `questions.type` is a string column.

**Frontend**
- Player: `PinCanvas` sizes the canvas to the image and supports high-DPI screens. Tap or drag
  to place the pin (its tip marks the point, its head sits above the thumb). Arrow keys nudge it,
  Enter locks in. The results screen shows your pin over the revealed target, and partial credit
  shows as "Partially correct".
- Host: `PinBoard` shows the image while the question is open, never the taps (so the room can't
  copy the crowd). At reveal and on the game-over card it shows every tap plus both circles.
- Editor (host app, used by hosts and admins): upload a file (downscaled to ≤ 1280 px and stored
  as a JPEG `data:` URL) or paste an image URL, click or drag to place the target, and set both
  radii with sliders that preview the circles.

**Other**
- `nginx.dev.conf`: `client_max_body_size 10m`, since images travel inside the question JSON.
- `scripts/simulate_players.py`: answers pin_the_spot questions, tapping near the target when
  given `--game-json`.
- **Bug fix:** `DELETE /admin/games/{id}` removed sessions from MySQL but left their Redis keys,
  which have no TTL. It now flushes the deletes, then clears each session's Redis state, the same
  way `DELETE /game/sessions/{id}` already did.
- **T6:** `sample_games/party_night_point_pick_rank.json` (party; all six types, three Pin the
  Spot questions with embedded images) and `sample_games/intro_networking_classroom.json`
  (classroom). Both are `"version": 1`.
- Context hierarchy: nested `CLAUDE.md` files updated for every directory touched.

### Changes from the original design doc
- **Image source:** `config.image_url` plus `image_width`/`image_height`, not a T8 `image_id`,
  because T8 isn't built yet. Width and height are stored with the question, so its scores can't
  change if an image is replaced. `image_id` can be added later as an alternative.
- **Rounding:** partial scores round to 2 dp, not whole points. The default `points_value` is 1,
  and whole-point rounding would turn every partial score into 0 or 1.
- **Radius limit:** `r_zero` ≤ the image diagonal, replacing the doc's fixed 1.5 cap, which didn't
  do what it claimed.
- **Edge tolerance:** circle edges are compared with a 1e-9 tolerance; floating-point error had
  scored a tap exactly on the edge as 999.99/1000.
- **COMPLETENESS:** the target is optional, allowing opinion questions such as "tap where you grew up".
