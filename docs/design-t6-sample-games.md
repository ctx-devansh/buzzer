## 1. Problem

T6 asks each member for **two game JSON files** under `sample_games/`: one classroom game
(educational, professional tone) and one party game (fun, broadly accessible). Each game must
contain at least one `multiple_choice`, `true_false`, `fill_in_the_blank` and `multi_select`
question, and must use both `ACCURACY` and `COMPLETENESS`. Across a member's two games, every
team T7 type (`put_in_order`, `pin_the_spot`) must appear in at least one game. Files are
`"version": 1`, must import cleanly into this application, and must be committed. The demo files
already in `sample_games/` don't count.

Satvik already wrote both games, but on branch `feature/pin-the-spot` (the T7 attempt before
this redo). They are not on `feature/t7-redo`:

## 2. Decisions (design discussion, 2026-10-05)

- **S1. Reuse, don't rewrite.** Cherry-pick both commits with `git cherry-pick -x` (keeps
  authorship and records the origin). The party game's content is unchanged. Its pin images and
  targets are then regenerated by the script (S3); the targets must not move.
- **S2. Add one ACCURACY `pin_the_spot` question to the classroom game.** It is a network
  topology where the student taps the default gateway. T6 doesn't require it (the party game
  already covers both T7 types), but it shows the canvas type in an educational setting.
- **S3. `scripts/make_pin_images.py` is the source of truth** for every pin image and its
  target. Targets are computed from the drawing's own coordinates, never typed in by hand.
- **S4. Tests.** An integration test imports every `sample_games/*.json`, and a unit test
  runs the script's `--check`.
- **S5. README.** Fix the import/export section and add a per-type format reference.
- **S7. Replace the starter files (user decision, 2026-10-05).** `sample_games/` ships only
  T6 games: the 12 starter files are deleted (`git rm`), and references to them are pointed at
  the new files. Devansh's games join the directory in his own change.
- **S6. Live check.** Import both games at :8080 and play a round of each with
  `simulate_players.py --game-json`. This also closes step 9 of the T7 plan.

3. Write the generator (§5.3) and run it. It rewrites `config` and `answer_data` for the five pin

## 4. Alternatives considered

- **A1. Write two new games.** That throws away correct, already-reviewed content for no gain.
- **A2. Cherry-pick and stop there.** T6 would be met, but the images would stay impossible to
  edit, the classroom game wouldn't show the canvas type, and nothing would prove that imports
  work.
- **A3. A classroom pin question on a TCP/IP layer diagram ("tap the Transport layer").** The
  layers are wide rectangles, but scoring uses circles. A circle that covers the box also
  reaches the neighbouring layer, so a wrong layer would get partial credit. The topology
  question has point-like devices that a circle fits.
- **A4. Device icons or "Router" labels in the topology.** Labels make the question trivial.
  Cisco-style icons test whether the student memorised symbols. Identical unlabelled boxes
  with IP addresses test reasoning: the gateway is the only device with an address in both
  subnets.
- **A5. Byte-for-byte PNG comparison in `--check`.** PNG bytes depend on the zlib and Pillow
  versions, so the check would fail spuriously. It compares decoded pixels with a tolerance
  instead (§5.3).
- **A6. Identify pin questions by an id field in the JSON.** `QuestionCreate` is
  `extra="forbid"`, so an extra key would fail import. Questions are identified by file,
  1-based index and an expected prompt prefix instead.

### 5.3 Generator: `scripts/make_pin_images.py`

**Prerequisite:** Pillow 10.1 or later (`ImageFont.load_default(size=…)`). Pillow is not in any
`requirements.txt`. The module docstring lists `pip install "pillow>=10.1"`, as
`simulate_players.py` lists its own prerequisites.

**Interface:**

- `python scripts/make_pin_images.py` renders every image and prints one line per plan row,
  `updated` or `unchanged`. A row is **updated** only if `--check` would report a difference for
  it (below): then its `config` and `answer_data` are rewritten from the fresh render. Otherwise
  it is **unchanged** and its stored PNG bytes are left alone, even if a fresh encode would give
  different bytes. A file is written only if at least one of its rows was updated. So re-running
  on another Pillow version doesn't churn the JSON.
- `python scripts/make_pin_images.py --check` writes nothing. It prints every difference and
  exits 1 if any exist, 0 otherwise.
- **Paths** are resolved from the script, never the working directory:
  `ROOT = Path(__file__).resolve().parents[1]`, files under `ROOT / "sample_games"`.
- **Plan mismatch** (the safety check below) raises `PlanError(ValueError)` from a shared
  `verify_plan()`, which both `check()` and the writer call first. The CLI catches it, prints it
  and exits **2 in both modes**. `check()` lets it propagate, so the unit test fails with the
  row named rather than a misleading list.
- Importable without side effects. It exposes `render(key) -> (PIL.Image.Image, (x, y))` and
  `check() -> list[str]` (the differences; empty means clean), which the unit test uses.
  `render` returns the target already **rounded to 4 dp** (`round(px / W, 4)`,
  `round(py / H, 4)`). The rounding happens once, there, and the written `answer_data` and
  `--check` both use those values. Without it, the number-line target is
  `0.7070000000000001`, not `0.707`.

**Plan table** (the only questions it touches; the index is 1-based):

| File | Q | Expected prompt starts with | Image key | `r_full` | `r_zero` | Grading |
|---|---|---|---|---|---|---|
| party | 3 | `Pin the colour` | `rainbow` | 0.03 | 0.10 | ACCURACY |
| party | 7 | `The hands fell off` | `clock` | 0.05 | 0.20 | ACCURACY |
| party | 8 | `Eyeball it` | `number_line` | 0.02 | 0.12 | ACCURACY |
| party | 11 | `No wrong answers` | `rainbow` | — | — | COMPLETENESS |
| classroom | 8 | `Host 10.0.1.10` | `topology` | 0.07 | 0.13 | ACCURACY |

**Safety:** before touching anything, for every row, the question at that index must have
`type == "pin_the_spot"`, the listed grading type, and a prompt starting with the listed prefix.
If any row fails, the script exits 2, names the row and writes **no** file. This catches
reordered questions instead of overwriting the wrong one.

**What it writes, per row:**

- `config` becomes exactly `{"image_url": "data:image/png;base64,<PNG>", "image_width": W,
  "image_height": H}`.
- ACCURACY rows: `answer_data` becomes `{"target": {"x": tx, "y": ty}, "r_full": …, "r_zero":
  …}`, with `tx`/`ty` rounded to 4 dp.
- COMPLETENESS rows: `answer_data` is left as stored (`{}`).
- Nothing else changes.

**File writing:** `json.dumps(bundle, indent=2, ensure_ascii=False) + "\n"`. Both cherry-picked
files already round-trip byte-identically under that call (checked), so the diff shows only
real changes.

**`--check` differences,** checked per row in this order (the first hit is the row's
difference):

1. `config` keys aren't exactly `image_url`/`image_width`/`image_height`, or `image_url` isn't a
   `data:image/png;base64,` URL that decodes to a PNG.
2. Size mismatch: the stored `image_width`/`image_height` or the decoded PNG's size differs from
   the render's.
3. ACCURACY rows: `answer_data` doesn't equal the expected dict exactly (`==` on the 4-dp
   target and the table's radii). COMPLETENESS rows: `answer_data != {}`.
4. Pixels: decode the stored PNG, `.convert("RGB")`, and compare with the render (also RGB).
   They differ when the mean absolute difference over all channels (0–255) is **> 2.0**. That
   tolerates antialiasing changes across Pillow versions but catches a real redraw.

Each difference is one line, `<file> Q<n> (<image key>): <reason>`.

**Encoding:** `image.save(buf, format="PNG", optimize=True)`, then base64. These are flat-colour
drawings: the cherry-picked data URLs are 1.2–4.8k characters, and the new ones should stay
well under 50k. That's far below `validate_pin_the_spot`'s 1,500,000-character limit and
nginx's `client_max_body_size 10m` at :8080 (`nginx/nginx.dev.conf`).

**Images.** Colours: background `#1e293b`, light `#f8fafc`, dark `#0f172a`, line grey
`#94a3b8`. Coordinates are pixels, origin top-left, ranges inclusive.

- **`rainbow`**, 720 × 180. Background fill. Bar at x 36–684, y 76–104. Pixel column x has
  colour HSV(h = 360·(x−36)/648, s = 1, v = 1), so x = 36 is red and x = 144 is pure yellow.
  The hue wraps on purpose: x = 684 is red again (a full hue circle). Neither prompt
  ("tap pure YELLOW", "tap your favourite colour") is hurt by a red right end. Compute with
  `colorsys.hsv_to_rgb(h / 360, 1, 1)` and convert each channel with `round(c * 255)` (not
  truncation). **Target** (144/720, 90/180) = **(0.2, 0.5)**.
- **`clock`**, 480 × 480. Background fill. Face: circle centred (240, 240), radius 216, fill
  light, 4 px dark outline. Twelve dark ticks on radial lines, measured from the centre: the
  four major ticks (12, 3, 6, 9) are 10 px wide from r = 158 to r = 202; the others are 5 px
  wide from r = 176 to r = 202. Centre dot: radius 8, dark. No hands. **Target** is the midpoint
  of the 3 o'clock tick, (240 + 180, 240)/480 = **(0.875, 0.5)**.
- **`number_line`**, 800 × 160. Background fill. Light line x 38–762, y 77–83. Three light
  ticks 5 px wide, centred at x = 40, 400 and 760, y 52–108. The value v maps to x = 40 + 7.2·v.
  **Target** for 73: (40 + 525.6)/800, 80/160 = **(0.707, 0.5)**.
- **`topology`**, 800 × 450. Background fill.
  - **Links:** grey, 4 px, drawn first, centre to centre: S1–R, R–S2, and each host to its
    switch.
  - **Devices:** three identical rounded rectangles (radius 8), 90 × 60, fill light, 3 px dark
    outline, **no text**. S1 is centred (220, 225), R (400, 225), S2 (580, 225).
  - **Hosts:** four rounded rectangles 70 × 46, fill `#cbd5e1`, 2 px dark outline, centred
    (70, 130) and (70, 320) on the left and (730, 130) and (730, 320) on the right.
  - **Text:** `ImageFont.load_default(size=18)`, light, anchor `"mm"` (centred).
    - Host labels sit 38 px below each host's centre: `10.0.1.10` at (70, 168), `10.0.1.11`
      at (70, 358), `10.0.2.20` at (730, 168), `10.0.2.21` at (730, 358).
    - Gateway interface labels: `10.0.1.1` at (310, 200), `10.0.2.1` at (490, 200).
    - Subnet captions: `10.0.1.0/24` at (145, 415), `10.0.2.0/24` at (655, 415).
  - **Target** is R's centre, (400/800, 225/450) = **(0.5, 0.5)**.
  - **Radii:** `r_full` 0.07 (56 px) covers the whole box (its half-diagonal is 54 px).
    `r_zero` 0.13 (104 px) ends before the nearest edge of either switch (180 − 45 = 135 px),
    so tapping a switch scores 0. The interface labels sit about 93 px from R's centre, so
    tapping a label scores a little partial credit (≈ 0.23). That is acceptable: the label
    belongs to R.
  - After the first render, look at the PNG once: no link may cross a label's text.

**The prompts carry what the images leave out (checked against the cherry-picked file).** The
number line has no text, but Q8's prompt says "the line runs from 0 (left end) to 100 (right
end), with a tick at 50. Tap where 73 is." The clock has no numerals or hands, and Q7 asks
"At quarter past, which hour mark does the MINUTE hand point at? Tap it.", so the answer is the
major tick at 3. The generator must not change any prompt. If an image ever needs text to make
sense, the prompt is the place to put it.

**Faithfulness check, run once in step 3, before the first write:** for the three existing party
images, the computed targets must equal the cherry-picked ones (read from the committed file,
`git show HEAD:sample_games/party_night_point_pick_rank.json`) within 0.005. They are (0.2, 0.5),
(0.875, 0.5) and (0.707, 0.5). The table's radii must also equal the stored ones exactly
(verified 2026-10-05: 0.03/0.1, 0.05/0.2, 0.02/0.12), so regeneration changes no scoring. If
either fails, stop and revisit this section rather than shipping a moved target.

### 5.4 Tests

- **`tests/integration/test_sample_games.py`**: parametrized over `sorted(glob("sample_games/*.json"))`,
  with ids equal to the file names. Resolve the glob against the repo root
  (`Path(__file__).resolve().parents[2] / "sample_games"`), not the working directory. It uses
  the existing `conftest.py` fixtures `base_url` and `admin_token` (session-scoped; `admin_token`
  depends on `docker_stack`), and imports `Api` and `Cleanup` with
  `from .test_host_admin_restructure import Api, Cleanup` (both are plain dataclasses, so no
  fixtures come along). `Api(base_url)` prefixes `/api`. Per file:
  1. One module-scoped fixture creates a single course for all files:
     `POST /admin/courses` with `json={"name": f"T6 sample games {uuid.uuid4().hex[:6]}", "semester": "Test"}`.
     Expect **201** and read `["id"]`. The course is left behind, as other tests do (there is no
     course DELETE).
  2. `POST /host/games/import` with the admin token,
     `files={"file": (name, path.read_bytes(), "application/json")}` and
     `data={"course_id": str(course_id)}`. Expect **201**. The body is `{"game_id": <int>}`. Add
     the id to `cleanup.games` straight away, before any further assertion.
  3. `GET /host/games/{game_id}/questions` returns as many questions as the bundle's top-level
     `questions` list, with the same `type` sequence.
  4. Steps 2–3 run inside a `try`, whose `finally` calls `cleanup.run()`
     (`Cleanup(api, admin_token)`), so a failed assertion still deletes the game. It deletes via
     `DELETE /admin/games/{id}` and accepts 204 or 404.

  Since S7 the glob covers only T6 games (ours, and later Devansh's). If a teammate's file
  fails, **stop and report it**; don't edit their content on this branch.
- **`tests/unit/test_pin_images.py`**: `pytest.importorskip("PIL")`. Load the script with
  `importlib.util.spec_from_file_location` from `scripts/make_pin_images.py` (path resolved from
  `__file__`, as above) and assert `check() == []`. Also assert
  `render("topology")[1] == (0.5, 0.5)`, `render("number_line")[1] == (0.707, 0.5)`,
  `render("clock")[1] == (0.875, 0.5)` and `render("rainbow")[1] == (0.2, 0.5)`. Exact `==` is
  correct because `render` rounds to 4 dp (§5.3). Also assert each image's `.size` equals the
  §5.3 dimensions.

## 7. Risks (self-critique)

- **Index-based plan table.** Reordering questions breaks it. Mitigation: the prompt-prefix and
  type check makes the script exit without writing. The table still needs a manual update.
- **Regenerated party images replace hand-made ones.** The pixels change, but the targets are
  checked to stay within 0.005 (§5.3), so scoring is unchanged.
- **Pillow isn't a declared dependency.** The unit test skips without it, so in an environment
  without Pillow the image check silently doesn't run.
- **Text rendering varies across Pillow/FreeType versions.** The 2.0 mean-difference tolerance
  should absorb it, because the labels are a small fraction of the topology image. A large
  version jump could still trip `--check`. The fix is to re-run the generator, not to raise the
  tolerance.
- **The sample-games test imports every T6 file, teammates' included.** A failing teammate file
  blocks the suite; the rule then is to stop and ask (§5.4).
- **Deleting the starter files (S7)** loses example content other docs mention
  (`design-put-in-order.md` names `cs_first_day.json` as its demo carrier). Those docs are
  historical records and stay as written; the files remain in git history.
- **Pedagogy.** The topology question tests address reasoning (which device has an address in
  both subnets), not recognising icons. That is intended (A4).
